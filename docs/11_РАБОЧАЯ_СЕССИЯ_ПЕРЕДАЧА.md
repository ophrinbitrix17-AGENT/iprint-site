# 11. Передача: «Рабочая сессия» — администратор сайта (с 26.11.2026)

## Роль
Универсальный администратор сайта iPrint: доводит сайт **из черновика до финала**. Заливает и обрабатывает фото, ставит финальные тексты владельца, правит вёрстку (пустоты и поля на ноутбуках/мониторах), цвета, кнопки, эффекты — практически любая работа по сайту. Владелец ставит задачи обычным языком (часто голосом); агент выделяет из сообщения **все** поручения в план.

## Иерархия (решение владельца 26.11.2026)
1. **Технические вопросы** «как сделано, где какие связи, почему так настроено» → сначала к **сессии-куратору** (та, что запустила Рабочую сессию: публикация, Cloudflare, DNS, бот, GitHub — сессия 2). Писать ей через `SendMessage`, одним коротким вопросом.
2. Владельцу — только то, что куратор не знает, и решения/факты/тексты/фото (его зона).
3. Владелец пишет только в Рабочую сессию; в сессию-куратор — нет.

## Обязательный порядок
- Прочитать: `00_СТАРТ…` → `../CLAUDE.md` (регламент: роли, общение блоками, рецензии) → `05_ЖУРНАЛ…` → `08_ИСТОРИЯ_СЕССИИ_1.md` → `10_ТЕХНИЧЕСКИЕ_УРОКИ.md` → «библия» по задаче.
- Каждая правка кода: ветка `etap3/<кратко>` → автотесты (без Firefox) → рецензенты по профилю (`.claude/agents/reviewer.md` = вёрстка, `reviewer-design.md`, `reviewer-geo.md`; запуск — `general-purpose` с промптом «Act as the reviewer defined in …») → исправления одним заходом → перепроверщик → показать владельцу скриншотами (телефон + компьютер, в т. ч. 1366×768, 1440×900, 1920×1080) → «ок» → `main`.
- Тексты — только `site/src/content/*.json`; цвета/размеры — только токены `site/src/styles/themes/2026-11.css`; фото — через конвейер `tools/ИЗОБРАЖЕНИЯ.md` + реестр `images.json`, `alt` на украинском. Правила фото — `../CLAUDE.md` §8 (ИИ не дорисовывает ткань/принт/шов).
- Тексты владельца не переписывать; заметил ошибку/штамп — предложить отдельно.

## Публикация и ограничения среды
- Тестовый сайт: `https://iprint-site.ophrinbitrix17.workers.dev` (noindex). Каждый push в `main` → автосборка Cloudflare → обновляется эта ссылка (1–3 мин).
- **`git push` агенту блокирует фильтр приложения** — не обходить. Давать владельцу команду (блок `powershell`): `cd "D:\!DSD\Software\Site\AGENT"; git push`. Проверка: `git fetch -q origin; git status -sb` → `## main...origin/main`.
- Владелец хочет «сначала тестовый вариант, после одобрения — main». Пока правку показывать локально (`wrangler dev` + скриншоты); по желанию настроить превью-ссылки для веток (Workers Builds, non-production branch deploy) — согласовать с куратором.
- Форма на тестовом сайте **настоящая**: заявки приходят менеджерам (`@iprintmanager`). Пробные — только «ТЕСТ агента» и с предупреждением владельца.
- Автотесты на GitHub (CI) присылают владельцу письмо при падении; логи агент не видит — просить скриншот красного шага.
- **Боевой домен iprint.com.ua не подключать** и `SITE_ENV=production` не ставить без явного «да» владельца (порядок — `00_СТАРТ…` §2 п. 3–4; детали — у куратора).

## Где материалы владельца
Финальные/новые тексты и фото владелец укажет сам в первом сообщении. Копировать в `AGENT/assets-inbox/` (вне `AGENT` — только чтение).

## Готовность
Когда материалы прочитаны и план правок составлен — коротко сообщить владельцу (уведомлением) «готов вносить правки» с планом блоками.
