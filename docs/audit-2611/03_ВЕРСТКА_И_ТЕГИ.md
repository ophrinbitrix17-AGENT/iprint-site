# Аудит 26.11 · Срез 3 — Вёрстка и теги (Б21)

Рецензент: reviewer-layout. Проверено: собранный `site/dist` (сборка 26.11 16:59, ветка `etap3/flock-uzor`, совпадает с исходниками) и живая тестовая ссылка (отличие от `dist` одно — фото «Флок», ветка ещё не опубликована). Файлы не менялись.

## Простыми словами для владельца

- **Заголовки (Б21) — в порядке.** На каждой из 7 страниц ровно один главный заголовок (h1), под ним разделы (h2), под разделами — пункты (h3). Ступеньки не пропущены, заголовки не используются «для красоты». Google, ИИ-поисковики и программы чтения с экрана видят правильное оглавление страницы.
- **Маленькие надписи над заголовками** («Виробничий партнер…», «Технології», «Послуги») сделаны обычным текстом, а не заголовком — это правильно. Позиционирование «Виробничий партнер для брендів одягу» в h1 переносить не нужно: h1 должен говорить, *что вы делаете* («Друк на тканині та пошив для брендів одягу»), это и ищут люди. Предлагаю лишь «склеить» надпись с заголовком специальным тегом (`hgroup`), чтобы машины точно понимали, что это одна шапка.
- **Подвал — главное замечание.** Подписи «Послуги», «Технології», «Контакти» в подвале выглядят как заголовки, но для машины это простой текст. А блоки «Послуги» и «Технології» объявлены «меню навигации», хотя ссылок в них нет ни одной. Для программы чтения с экрана это «пустое меню». Если подвал будете упрощать (Б10) — проблема уйдёт вместе с ним; если оставите — нужна правка на 10 строк.
- **Пустая полоса после перехода по меню (Б1, Б17) — объяснение.** Сайт специально оставляет под шапкой запас 12 px, чтобы шапка не закрывала начало раздела. Но у каждого раздела есть ещё собственный верхний отступ: на компьютере 112 px. Вместе получается ~124 px пустоты между меню и словом «Технології». У блока заявки отступ начинается с лаймовой полосы (рамка 6 px сверху) — поэтому «Розрахувати» ставит лаймовую полосу прямо под меню. Лечится одной строкой CSS: при переходе по ссылке страница «съедает» верхний отступ раздела (сам отступ при обычной прокрутке остаётся). Точную величину зазора (16–24 px) выбирает срез 1 (композиция).
- **Анимации** уважают системную настройку «уменьшить движение» — всё в порядке. Плавной прокрутки на сайте нет, переход мгновенный.
- **Надпись «ФОТО ТИМЧАСОВЕ»** — это настоящий текст страницы: программа чтения с экрана произносит её *раньше* главного заголовка, и её видят Google и ИИ. Для превью терпимо, перед запуском — обязательно убрать вместе с временными фото (или сейчас скрыть от машин).
- Остальное — мелочи: карточки и пункты меню лучше оформить списками (машина скажет «список из 4»), блок «Є ідея…» не должен называться «разделом», нижняя липкая панель — вне разметки страницы. Блокирующих проблем нет.

### Желательные

**Ж1. Подвал: `<nav>` без ссылок и «заголовки» абзацами** — `site/src/components/Footer.astro:22–36`.
Сейчас все карточки `href: null` (`home.json:91–142`), поэтому `nav «Послуги»` и `nav «Технології»` — ориентиры навигации, в которых нет ни одной ссылки; программа чтения с экрана перечислит их в списке «меню» — пустыми. Подписи `p.ftr__h` (стр. 23, 29, 35) визуально — заголовки списков, а машине не видны как заголовки (WCAG 1.3.1, Б2 §7 «семантика»).
Исправление (если подвал остаётся в нынешнем виде, см. Б10 в срезах 4/5):
```astro
---
const linked = (cards) => cards.some((c) => c.href);
const ProdTag = linked(home.products.cards) ? 'nav' : 'section';
const TechTag = linked(home.tech.cards) ? 'nav' : 'section';
---
<ProdTag aria-labelledby="ftr-poslugy">
  <h2 class="ftr__h" id="ftr-poslugy">{home.products.eyebrow}</h2>
  <ul class="ftr__list" role="list">…</ul>
</ProdTag>
<TechTag aria-labelledby="ftr-tekhnolohii">
  <h2 class="ftr__h" id="ftr-tekhnolohii">{home.tech.eyebrow}</h2>
  <ul class="ftr__list" role="list">…</ul>
</TechTag>
<section aria-labelledby="ftr-kontakty">
  <h2 class="ftr__h" id="ftr-kontakty">{site.ui.footerContacts}</h2>
  <ul class="ftr__list" role="list">…</ul>
</section>
```
Стили не меняются: `base.css:18` уже сбрасывает отступы у `h2`, размер и вид задаёт класс `.ftr__h` (`Footer.astro:56`) — проверить скриншотом, что подвал выглядит как прежде. Если по Б10 подвал сократится до «лого + телефон + почта + политика» — `nav` и подписи убрать совсем, оставить `<address>` с контактами (тег для контактов владельца сайта).

**Ж2. Переход по якорю съедает отступ раздела** — `site/src/styles/base.css:4`, `site/src/components/HardCta.astro:25,35`.
`scroll-padding-top` на `html` оставить (он же не даёт шапке закрывать поле при переходе Tab — WCAG 2.4.11). Добавить в `base.css` после строки 40:
```css
/* переход по якорю: раздел начинается почти сразу под шапкой, отступ секции «уходит» под неё */
.section[id] { scroll-margin-top: calc(var(--anchor-gap) - var(--section-y)); }
.cta[id]     { scroll-margin-top: calc(var(--anchor-gap) - var(--cta-y)); }
```
в `themes/2026-11.css` — токены `--anchor-gap: 12px` (итого зазор под шапкой = 12 + 12 = 24 px; величину утверждает срез 1) и `--cta-y: 48px` / `88px` на ≥1100; в `HardCta.astro:25,35` заменить `padding: 48px 0` / `88px 0` на `var(--cta-y) 0`. Отрицательный `scroll-margin` допустим по спецификации и работает в Safari 14.1+ (наш минимум iOS 16.2). Обычная прокрутка не меняется. Для `#zapyt` лаймовая рамка уйдёт под шапку — лаймовой полосы под меню не будет. Добавить автотест: после клика «Технології» `getBoundingClientRect().top` у `.eyebrow` в `#tekhnolohii` = `header-h + 24 ± 2` на 375 и 1920.

**Ж3. Надпись + заголовок + подзаголовок — одной группой** — `site/src/components/Hero.astro:22–24`, `site/src/components/CardGrid.astro:14–15`.
Обернуть в `<hgroup>` (HTML Living Standard разрешает `p` до и после заголовка внутри `hgroup`):
```astro
<hgroup class="hero__head">
  {data.eyebrow && <p class="eyebrow">{data.eyebrow}</p>}
  <h1 class="h1" id="hero-title">{data.title}</h1>
  {data.lead && <p class="lead hero__lead">{data.lead}</p>}
</hgroup>
```
то же в `CardGrid` (eyebrow + h2). Машина однозначно связывает «Виробничий партнер для брендів одягу» с h1, а «Технології» — с h2. Стили не меняются (`hgroup` — блочный элемент без оформления; `margin: 0` при необходимости).

**Ж4. Карточки и меню — списками** — `site/src/components/CardGrid.astro:16–18`, `site/src/components/Header.astro:11–26, 37–53`.
Б2 §7 «списки — списками». Сетки карточек — `<ul class="grid grid--…" role="list">`, каждая карточка в `<li>` (лесенка `:nth-child` и сетка работают на `li`; карточке внутри `li` дать `height: 100%`). Ссылки меню — `<ul role="list"><li>…</li></ul>`. Программа чтения скажет «список, 4 элемента» — человек сразу знает объём. `role="list"` нужен, потому что Safari/VoiceOver снимает семантику со списков с `list-style: none`; то же добавить в `Advantages.astro:9`, `Complex.astro:18`, `Footer.astro` (`.ftr__list`), `ContentSections.astro:17` при условии, что у них убраны маркеры.

### Замечания на будущее
- Когда у карточек появятся `href`, вся карточка станет одной ссылкой (`Card.astro:12`): её имя = alt фото + заголовок + текст (≈30 слов, alt первым). Тогда: `alt=""` у фото внутри ссылки (или `aria-labelledby` на заголовок карточки).
- Если будет добавлена плавная прокрутка — только внутри `@media (prefers-reduced-motion: no-preference)`. Сейчас `base.css:91–93` корректно гасит переходы; анимаций (`@keyframes`) и View Transitions на сайте нет.
- «ДТФ» (h3) и «DTF у рулонах» (h3) — два написания одного термина; для поиска и ИИ лучше одно основное + второе в тексте (решение — срезы 4/6).
- Мягкий перенос в «Шовко­трафарет» (`&shy;`) поисковики и экранные чтецы игнорируют — оставить; в Schema уже чистое `title`.
