# Б3. Библия GEO / SEO iPrint (редакция 17.11.2026)

Обязательна перед созданием или изменением любой страницы, текста, разметки, ссылок. Основа — `research/R3_GEO_SEO_2026.md` (там 40 источников, таблица JSON-LD и детали). **Содержание** ответов, цифры, цены — зона владельца; агент отвечает за то, чтобы сайт был **технически и структурно** идеален для ИИ и поиска.

---

## 1. Главный принцип
Google (май 2026): GEO = нормальное SEO. AI Overviews/AI Mode используют тот же индекс. «Специальные ИИ-файлы», нарезка текста под ИИ и особая «ИИ-разметка» в Google ничего не дают. Работает: **оригинальный экспертный контент + чистый HTML + сущность бренда + упоминания на сторонних сайтах + свежесть**.
- ИИ всё чаще цитирует страницы вне топ-10 (Ahrefs: доля цитат из топ-10 упала с 76 % до 38 % за 2025–2026) → много точных ответов на узкие вопросы = шанс.
- Факты, цифры, цитаты, источники в тексте повышают цитируемость (исследование Princeton GEO); набивка ключевых слов — нет.
- Упоминания бренда на других сайтах важнее обратных ссылок (Ahrefs: корреляция 0,664 против 0,218).

## 2. Техника (обязательно)
- **Весь смысловой текст — в исходном HTML.** ИИ-боты не выполняют JavaScript. Цены, сроки, ответы, контакты, JSON-LD — не подгружать скриптами. Аккордеоны — только `<details>` с текстом в HTML.
- `robots.txt`: разрешить всё, указать sitemap. Явно не блокировать: Googlebot, Bingbot, OAI-SearchBot, ChatGPT-User, Claude-SearchBot, PerplexityBot (нужны для ответов) и обучающих GPTBot, ClaudeBot, Google-Extended, Applebot-Extended (чтобы модели «знали» iPrint).
- ⚠️ **Cloudflare:** управляемый robots.txt и «AI crawl control» могут сами блокировать ИИ-ботов. После подключения домена — проверить живой `/robots.txt` и настройки панели. Обязательный пункт чек-листа запуска.
- `sitemap.xml` (@astrojs/sitemap), `lastmod` = дата реального изменения содержания, не сборки.
- IndexNow (через Cloudflare Crawler Hints или при сборке).
- `llms.txt` — **не приоритет** (Google игнорирует; 97 % таких файлов никто не запрашивает). Можно добавить как мелочь, ничего не ждём.
- `lang="uk"`, без hreflang (один язык). Canonical на каждой странице. ЧПУ латиницей: `/dovidnyk/shovkotrafaret/`.
- Скорость и Core Web Vitals — см. Б2.

## 3. Разметка Schema.org (JSON-LD)
- FAQ-сниппеты в Google отключены (7 мая 2026), звёзд за собственные отзывы нет. Разметка нужна для **однозначного описания сущности**, не ради «звёздочек».
- **Одна сущность компании** `LocalBusiness` с `@id: https://iprint.com.ua/#org` — на всех страницах; остальные ссылаются на неё.
- Набор: `LocalBusiness` + `WebSite` (все страницы), `BreadcrumbList` (кроме главной), `Service` (услуги; `Offer`/цена — только утверждённые), `Article`/`TechArticle` (технологии, с автором и датами), `Article` + `FAQPage` (Довідник), `AboutPage` + `Person`, `ContactPage`, `Product` + `Offer` (DTF в рулонах, если будет цена за метр).
- **Генерировать JSON-LD из тех же данных, что и видимый текст** (`src/content/`) — разметка и страница не расходятся. Проверка: Rich Results Test + validator.schema.org.
- Не размечать собственные отзывы как AggregateRating.

## 4. Структура контента
- Один H1, вопрос-заголовки H2/H3 формулировками людей, якоря на каждом вопросе.
- **Довідник — «хаб и спицы»:** хаб `/dovidnyk/` → тематические страницы (8–15 вопросов) → отдельные страницы для больших вопросов (напр. «Шовкотрафарет чи DTF для партії 50 футболок»). Каркас — `content-drafts/ДОВІДНИК_КАРКАС.md`.
- **Формат ответа:** 1–2 первых предложения — сам ответ (с цифрой/условием) → пояснение → таблица/список → фото реальной работы → ссылки на услугу и 2–3 связанных вопроса.
- На страницах Довідника и технологий — дата «Оновлено» и автор (технолог/основатель, с именем) — сигнал экспертности.
- Цены: «від X грн за одиницю при тиражі від N шт.» + от чего зависит. Только утверждённые владельцем.
- **Не делать** страниц-клонов по городам («DTF Одеса / Київ / Львів») — нарушение политики Google о массовом контенте.
- **Не делать** SEO-простыни, keyword stuffing, сгенерированный невычитанный текст.
- Перелинковка: каждая услуга ↔ технологии ↔ вопросы Довідника ↔ кейсы.

## 5. Язык
- Украинский. Для Одессы русские написания («шелкография», «печать на футболках») — максимум одно естественное упоминание на страницу, без набивки. Ключевые запросы — гипотезы, проверять в Keyword Planner (зона владельца).

## 6. Сущность бренда (зона администрирования, по команде владельца)
- Google Business Profile, одинаковые название/адрес/телефон везде (NAP), `sameAs` на все профили (Instagram, Telegram, Facebook, каталоги).
- Упоминания на сайтах клиентов (кейсы со ссылками), отраслевых каталогах — список каталогов составить отдельно.

## 7. Переезд iprint.od.ua → iprint.com.ua
- 301 с **каждого** старого адреса на соответствующий новый (не всё на главную, если есть соответствие).
- Search Console: «Смена адреса». Держать редиректы минимум 180 дней–1 год; **рекомендуется — бессрочно**, домен продлевать.
- Обновить адрес сайта в Google-профиле, соцсетях, каталогах.

## 8. Измерение
- Search Console (отчёт «Generative AI», доступен всем с 31.08.2026), Bing Webmaster Tools «AI Performance».
- GA4: канал «AI Assistant» + своё правило для perplexity.ai, copilot и др.
- Ежемесячный ручной тест 15–20 фиксированных запросов в 6 ассистентах (ChatGPT, Gemini, Perplexity, Copilot, Claude, Google AI Mode) — протокол ведёт владелец в своём VLM-проекте; агент даёт технические данные.

## 9. Чек-лист GEO/SEO для каждой страницы
- [ ] Один H1, вопрос-заголовки, якоря, хлебные крошки.
- [ ] `<title>` (≤ 60 знаков), meta description (≤ 155), canonical, Open Graph (картинка 1200×630).
- [ ] JSON-LD по типу страницы, валиден, совпадает с видимым текстом.
- [ ] Весь смысловой текст в HTML без JS.
- [ ] Дата «Оновлено» (Довідник, технологии), автор.
- [ ] Перелинковка на услуги/технологии/вопросы.
- [ ] Страница в sitemap с правильным `lastmod`.
- [ ] `alt` у всех фото — по-украински, по делу.
- [ ] Нет выдуманных фактов и неутверждённых цен.
