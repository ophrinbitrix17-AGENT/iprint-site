# Б4. Протокол тестирования iPrint (редакция 17.11.2026)

Тестирование — **обязанность агента** (решение владельца). Выполняется после рецензий, до показа владельцу. Основа — `research/R2_стандарты_веб-верстки_2026.md`, раздел 8.

## 1. Матрица
| Платформа | Чем проверяем | Обязательно |
|---|---|---|
| Windows — Chrome, Edge, Firefox | Playwright (Chromium, Firefox) | да |
| Linux — Chrome, Firefox | Playwright (те же движки) | да |
| Android — Chrome | Playwright: эмуляция устройств (Pixel, Galaxy) — движок Chromium | да |
| iPhone — Safari | Playwright WebKit + эмуляция iPhone | да, **но это приближение** |
| iPhone — реальное устройство | Владелец открывает превью-ссылку на своём iPhone по чек-листу агента (или облачный сервис реальных устройств, если подключим) | перед каждым релизом главных шаблонов |
| macOS — Safari | Playwright WebKit | по возможности |

**Важно:** WebKit в Playwright ≠ настоящий Safari на iOS (шрифты, «чёлка», адресная строка, жесты). Поэтому перед публикацией шаблонов — короткая проверка на живом iPhone.

## 2. Ширины экрана
Телефоны: **320, 360, 375, 390, 393, 414, 430**. Планшет: **768**. Компьютер (с 900 px): **910, 1024, 1093, 1280, 1366, 1440, 1920** (910 и 1093 — ноутбук 1366 с масштабом Windows 150 % и 125 %; 1024 — планшет лёжа, показывается версия компьютера).
Плюс ландшафт телефона (844×390).

## 2а. Базовые экраны — после КАЖДОЙ правки (правило владельца, 27.11.2026)
После любой правки вёрстки, фото или текстов — перепроверить адаптацию хотя бы на базовых экранах (размер — CSS-пиксели окна без панелей браузера):

| Экран | Окно | Что должно быть |
|---|---|---|
| Телефон | 390×844 | одна колонка, кнопка «Меню» |
| Планшет | 768×1024 | две колонки, кнопка «Меню» |
| Планшет лёжа | 1024×768 | версия компьютера |
| Ноутбук 1366×768 | 1366×657 | версия компьютера |
| Ноутбук 1366×768, масштаб Windows 125 % | ≈ 1093×530 | версия компьютера: меню в шапке, фото Hero справа, карточки в ряд |
| Ноутбук 1366×768, масштаб 150 % | ≈ 910×430 | то же |
| Компьютер | 1440×900 (окно 1440×789) | версия компьютера |
| Full HD | 1920×1080 (окно 1920×969) | версия компьютера |

Автотест — `site/tests/adaptive.spec.ts` (входит в обычный прогон): нет горизонтальной прокрутки; на «компьютерных» экранах меню в шапке, фото Hero справа от текста, Hero не занимает весь экран, карточки и пункты стоят в ряд. Скриншоты до/после — первым экраном на этих размерах (пример скрипта — `docs/10_…`). Масштаб Windows и браузера = меньшее окно в CSS-пикселях: 1366 / 1,25 ≈ 1093, 1366 / 1,5 ≈ 910, 1920 / 1,5 = 1280.

## 3. Что проверяется в каждом прогоне
1. **Скриншоты** всех страниц на всех ширинах в обеих темах (светлая/тёмная) — сравнение с предыдущим прогоном (визуальная регрессия).
2. Нет горизонтальной прокрутки (`scrollWidth ≤ innerWidth`).
3. Первый экран телефона: виден H1 и главная кнопка.
4. Меню: открывается/закрывается, работает с клавиатуры, `aria-expanded`.
5. Переключатель темы: меняет тему, запоминает выбор, нет вспышки при перезагрузке.
6. Форма: валидация, отправка на тестовый Telegram-чат, сообщение об успехе/ошибке, защита от спама.
7. Ссылки: нет битых (внутренние и внешние), `tel:` и Telegram открываются.
8. Lighthouse (мобильный профиль): Performance, Accessibility, Best Practices, SEO ≥ 90.
9. Доступность: автоматическая проверка axe-core — 0 серьёзных нарушений.
10. `prefers-reduced-motion`: анимации отключены.
11. Разметка: JSON-LD валиден (validator.schema.org), robots.txt и sitemap доступны.

## 4. Инструменты (ставятся в `site/` на этапе каркаса)
- Playwright (Chromium, Firefox, WebKit) — сценарии в `site/tests/`.
- @axe-core/playwright — доступность.
- Lighthouse CI — производительность.
- Скрипт `npm run test:all` — полный прогон, отчёт в `site/test-results/`.
- До появления `site/` — визуальные макеты проверяются во встроенном браузере (эмуляция телефона/планшета/компьютера).

## 5. Отчёт владельцу
Коротко, простыми словами: что проверено, где, что нашлось и исправлено, что осталось и требует его телефона (iPhone-чек-лист из 5–7 пунктов).
